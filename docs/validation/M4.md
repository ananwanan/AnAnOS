# M4 syscall -> filesystem validation

Date: 2026-10-04. Base `f5fd226`, branch `codex/syscall-filesystem`.
Windows x86_64, Rust 1.99.0, `aarch64-unknown-none`, LLVM clang/LLD 22.1.0.
This records implementation/build/host-test evidence; Raspberry Pi acceptance
is pending. The M1/M2/M3 checks and hardware safeguards remain intact.

## Implemented path

SVC -> process FD -> VFS -> immutable USTAR or writable RAM file, including
whole-range input/output validation, fixed-width ABI outputs, paths, directories,
cwd, shared open-file offsets, descriptor inheritance/dup and cleanup. Four CPU0
process slots support round-robin yield/wait/timer switching, static ELF roots,
normal argv/envp/auxv stacks, spawn, staged exec replacement, exit and wait.
All roots are built offline; active tables are not mutated. Kernel root/full
TLBI precede reclamation. Failed ELF construction preserves the caller; invalid
wait output does not reap. See [implementation and bounds](../filesystem.md).

Prior work review found no existing M1-M3 production invariant failure. The
follow-up carries fd through the shared write dispatcher and retains EBADF ->
length -> pointer precedence, centralizes bidirectional user copies, translates
public open flags to VFS-private flags, and extends the unified image checker.
New scheduler review corrected temporary IRQ-mask capture and allows a saved
user PC/SP to fault at EL0 after resume without aborting other processes.

## QEMU observation and limit

QEMU 11.1.0 `raspi4b` ran an unmodified development ELF snapshot using the
normal QEMU firmware-style EL2 boot stub, a tiny x0/PC handoff, and a synthetic
2 GiB DTB. Snapshot SHA256:
`556EAB6FBB3CD9326F16E384A5F6874343E30ACC6975B48EB1A88C4952DCE19F`.
This predates the final saved-SP/fixture diagnostics refinements; no M4 behavior
is inferred from it. [Captured emulated UART](M4-qemu-uart.txt) observes EL1 boot,
mailbox, framebuffer allocation, physical-page/heap self-tests and 40 timer ticks.

MMU preparation safely reports `Cpu(CoherencyDisabled)` and retains the device
diagnostic path; EL0 and M4 were skipped. QEMU's
[Cortex register model](https://gitlab.com/qemu-project/qemu/-/raw/v11.1.0/target/arm/cortex-regs.c)
defines CPUECTLR_EL1 as constant zero, so the required Cortex-A72 SMPEN bit
cannot be established. The real-hardware guard was retained. This is a blocked
emulated M4 execution, not a passed M4 end-to-end test or hardware evidence.
`scripts/qemu_smoke.py` snapshots its ELF input, bounds execution to 60 seconds,
records UART/summary, and stops only its own emulator process. It is optional
and is not part of the build acceptance script.
