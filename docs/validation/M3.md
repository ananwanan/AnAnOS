Entry/load addresses remain kernel `0x200000`, bootloader `0x80000`. Default
and MMU-only variants do not link the EL0 runner. Each image was checked against
its ELF immediately after its build, before the next variant overwrote it.

EL0 tests include independently decoding raw AP/PXN/UXN/nG descriptors,
code/data/guard/kernel/MMIO isolation, overflow and whole-buffer validation,
discontiguous physical copy chunks, same-VA/different-PA roots, other-task
ownership rejection and every task-construction allocation-failure boundary.
Original DTB/physical-page/heap/MMU regressions and stress checks remain.

Assembly and Rust layout agree on the 816-byte exception frame and SP/FAR
offsets800/808. The runner frame is256bytes; payloads are352/20/24/28/4bytes.
Disassembly static direct-call estimates are about26.4KiB for the largest boot
path and10.1KiB for the suspended runner plus lower-EL syscall path, within the
64KiB kernel stack. Indirect formatting/panic recursion is outside these estimates.

The audit found and fixed a pending-EL1-tick timeout race. The runtime now budgets
only actual timer IRQs from EL0; root restore/full TLBI precede page reclamation.
SVC does not add4to ELR. UserFP state is preserved while kernelFP state is reset/
restored. Clearing UMA/DZE/UCI and CNTKCTL prevents unprivileged IRQ masking,
cache maintenance and physical-timer reconfiguration.

## Hardware acceptance pending

No boot-drive installation, UART upload or new board output was performed.
M1/M2 and Gate A remain unaccepted on hardware until real UART/HDMI evidence
shows MMU/AT probes, Hello/SVC+exit, controlled isolation/RO/stack faults, three
EL0 timer IRQs, correct return to EL1, complete page reclamation and subsequent
timer ticks. Static host checks do not execute the embedded EL0 programs.
