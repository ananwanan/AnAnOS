# M1 验证记录

## 开发机结果

Windows x86_64，Rust/Cargo 1.99.0，裸机 target `aarch64-unknown-none`。
缺失的 target 和 cargo-binutils 已安装，镜像使用 `rust-objcopy` 生成。

| 检查 | 结果 |
| --- | --- |
| `cargo fmt --all -- --check` | 通过 |
| `cargo check --workspace` | 通过；占位 workspace crate 也明确 no_std |
| `cargo test -p kernel --lib --target x86_64-pc-windows-msvc` | 35 通过，0 失败 |
| `cargo build -p kernel` / `cargo build -p bootloader` | 通过 |
| `cargo build --release -p kernel -p bootloader` | 通过 |
| 两个 Windows 镜像构建脚本 | 通过 |
| ELF 架构与入口 | AArch64；kernel `0x200000`，bootloader `0x80000` |
| VBAR 向量/栈符号对齐 | 2048/16 字节检查通过 |
| raw image 检查 | 非空、未混入 ELF 格式、未超过协议上限 |
| `git diff --check` | 通过 |

debug 镜像：`target/kernel8.img` 为 125912 字节，
`target/bootloader8.img` 为 7786 字节。BSS 位图和栈不被作为镜像 payload
传输；它们位于 linker 规定范围，并在启动/内存保留逻辑中单独处理。

35 项测试包含 DTB 截断/字节变异、版本/布局/容量、32/64 位 cells、静态/
动态保留区、1 GiB CMA 放置、RAM 空洞、事务性失败、页耗尽/释放/复用、
4 GiB 以上地址，以及 DTB 到页分配器的完整排除检查。

补充静态检查：AArch64 汇编和反汇编确认异常向量入口间距 128 字节，
800 字节帧保存/恢复 q0–q31 和 FPCR/FPSR，bootloader 使用 x0 传 DTB，
独立寄存器跳转 `0x200000`。目标代码生成包含 `+strict-align`，DTB 解码
及字符串字节访问未依赖未对齐的宽加载。

复现统一检查：

```powershell
.\scripts\check_windows.ps1
```
